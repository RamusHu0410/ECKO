# ECKO Backend

The Flask backend for ECKO: it turns a hummed recording into notes, arranges an
accompaniment around them, lets users reshape the song by talking to it, and stores
users' recordings and discussion-hub posts.

## Overview

| Layer | Where | What it does |
| --- | --- | --- |
| Hum analysis | `src/app/audio/`, `audio_to_notes/` | Cleans the uploaded WAV and detects notes, tempo, key and tuning (`librosa`, `scipy`, `pedalboard`). |
| Accompaniment engine | `accompanist/` (uv workspace package) | Melody → chord progression → MIDI/WAV (`music21`, `pretty-midi`, `mido`, FluidSynth). |
| Talk mode | `src/app/talk/`, `routes/talk.py` | Voice commands like "make it faster" change the song settings (Google Gemini + ElevenLabs TTS). |
| App data | `routes/account.py`, `posts.py`, `users.py` | Auth0-protected API backed by TigerData (PostgreSQL) via SQLAlchemy + Flask-Migrate. |

Stack: Python ≥ 3.12, Flask 3 (app factory in `src/app/__init__.py`), managed with `uv`.

## Setup

1. Install dependencies (includes the `accompanist` workspace package and dev tools):
   ```bash
   cd backend
   uv sync
   ```
2. Create `backend/.env` with:

   | Variable | Purpose |
   | --- | --- |
   | `DATABASE_URL` | TigerData / Postgres connection string (required, no SQLite fallback outside tests) |
   | `AUTH0_DOMAIN`, `AUTH0_API_AUDIENCE` | Auth0 tenant and API identifier used to validate JWTs |
   | `SECRET_KEY` | Flask secret |
   | `GEMINI_API_KEY`, `ELEVENLABS_API_KEY` | Talk mode (only needed when `/talk` is used) |
   | `FLASK_ENV` | `development` (default), `production`, or `testing` |
   | Optional | `UPLOAD_FOLDER`, `RECORDINGS_FOLDER`, `STORAGE_DIR`, `SOUNDFONT_PATH` |

3. Check the database connection and create the schema:
   ```bash
   cd src
   uv run python -m app.db_utils          # -> Database connection successful
   export FLASK_APP="app:create_app"
   uv run flask db upgrade
   ```

WAV rendering needs FluidSynth and a soundfont (see `accompanist/soundfonts/` or set `SOUNDFONT_PATH`).

## Run

```bash
cd backend/src
uv run flask --app app:create_app run --port 8000
```

Or without the Flask CLI:

```bash
cd backend/src
../.venv/bin/python -c "from app import create_app; create_app('development').run(host='127.0.0.1', port=8000)"
```

A VPN may be required to reach the TigerData service from some networks.

In development the frontend's Vite server proxies `/api/*` to port 8000. It strips the
`/api` prefix (`/api/upload` → `/upload`) except for the Auth0 routes (`/api/me`,
`/api/recordings`, `/api/posts`, `/api/users`), which Flask serves under `/api` itself.
In production, Vercel serves `wsgi:app` (see `pyproject.toml` and the root `vercel.json`).

## API

### Hum & accompaniment (no auth)

| Method & path | Description |
| --- | --- |
| `GET /health` | Health check |
| `POST /upload` | Multipart `file` (.wav). Returns the detected melody, tempo, key/mode, tuning, warnings, and a generated accompaniment with a playable URL. |
| `GET /song/<name>` | Streams a WAV/MIDI generated by `/upload` |
| `GET /accompaniment/styles` | Lists styles: `piano`, `pop`, `cinematic`, `classical` |
| `POST /accompaniment/generate` | Melody in, MIDI/WAV/JSON out (see below) |

### Talk mode (`/talk`)

| Method & path | Description |
| --- | --- |
| `POST /talk/voice` | Voice recording + current settings → what was heard, new settings, reply id |
| `GET /talk/speech/<id>` | The gnome's spoken reply, streamed as MP3 |
| `POST /talk/song` | Saved hum + settings → the remade song as WAV |
| `POST /talk/notes` | Saved hum + settings → sung notes, played notes and pitch contour (JSON) |

### App data (Auth0 bearer token required)

| Method & path | Description |
| --- | --- |
| `GET /api/me` | Current user (created on first authenticated call) |
| `POST /api/recordings` | Save a finished song (multipart `file`, optional `title`, `style`) |
| `GET /api/recordings` | List your recordings |
| `GET /api/recordings/<id>/file` | Download a saved recording |
| `GET/POST /api/posts` | List (paginated, `?search=`) or create posts |
| `GET/DELETE /api/posts/<id>` | Read or delete a post |
| `GET /api/posts/<id>/audio` | Stream the post's attached recording |
| `GET/POST /api/posts/<id>/comments` | List or add comments |
| `DELETE /api/posts/<id>/comments/<comment_id>` | Delete a comment |
| `POST/DELETE /api/posts/<id>/like` | Like or unlike a post |
| `GET /api/users/<username>` | Public profile |

Saved audio files live in `storage/` (`<STORAGE_DIR>/recordings/<user_id>/<recording_id>.<ext>`);
the database holds only their metadata.

## `/accompaniment/generate` in detail

Request body:

```json
{
  "melody": [
    {"hz": 60, "start": 0, "duration": 1},
    {"hz": 64, "start": 1, "duration": 1},
    {"hz": 67, "start": 2, "duration": 1},
    {"hz": 72, "start": 3, "duration": 1}
  ],
  "style": "classical",
  "format": "midi"
}
```

- `hz` is a MIDI pitch number (60 = middle C); `start` and `duration` are in beats.
- `key`, `mode` and `tempo` are optional (key is auto-detected when omitted).
- `format`:
  - `json`: metadata only, e.g. `{"status":"success","key":"C","mode":"major","style":"pop","progression":["C"],"num_notes":4,"warnings":[]}`
  - `midi` (default): `.mid` file, `audio/midi`, with accompaniment and melody tracks
  - `wav`: `.wav` file, `audio/wav` (needs FluidSynth)

Example:

```bash
curl -X POST http://127.0.0.1:8000/accompaniment/generate \
  -H "Content-Type: application/json" \
  -d '{"melody":[{"hz":60,"start":0,"duration":1},{"hz":64,"start":1,"duration":1}],"style":"piano","format":"wav"}' \
  --output out.wav
```

The engine writes one chord per bar (4 beats), so a melody spanning only a few beats gives
a one-chord progression. Use an 8-bar melody (starts from 0 up to ~31) to hear a full
progression such as C F G C Am F G C.

On the frontend, `generateAccompaniment()` (in `Frontend/Kelvin's files/api/`) POSTs the
melody to `/api/accompaniment/generate` with `format=wav` and returns an object URL that
can be played with `new Audio()` or an `<audio>` element.

## Tests

```bash
cd backend/src
uv run pytest tests -v
```

Tests cover the app factory, configuration, audio processing and API routes. They run
against in-memory SQLite and a stubbed Auth0 verifier, so they never touch Tiger Cloud or
need API keys. The `accompanist` package has its own suite in `accompanist/tests/`.
